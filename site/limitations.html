Limitations and release status

This page is deliberately long. A preview that lists what it cannot do is more useful than one that lets you find out.

Release status

Development preview, unsigned
The published v0.1.0-alpha.2 archives are a GitHub prerelease with no Apple notarization and no Windows code signing. Build provenance is attested; that is not code signing. Signed installers are selected for later and not delivered.
The published archive is far behind main
It contains inspect only. Every other workflow on this site exists on main, passes CI there, and is not in any published archive until the owner tags the next prerelease.
No finished-product claim
The release acceptance checklist is open. Its system-acceptance gate (#109) has not been met, and nothing here should be read as a claim that it has.
No license terms, no trial, no support offering
Readmit's own license terms are not published; the repository ships third-party notices only. The adopted evaluation, billing and support policies in the product decisions are directions, not implemented or offered services. Every workflow on this site runs without an entitlement.
No screenshots
The desktop shell exists and is tested, but no built release has been captured yet. Screenshots will be added from a built release; none will be mocked.

Not implemented

  • Database observations of any kind: PostgreSQL, SQL Server, Oracle, ODBC. Selected, not built.
  • Mirth Connect or Open Integration Engine export adapters. Selected, not built.
  • An SSH or SFTP client. A remote export is collected through your own read-only program.
  • Collecting from an application interface declared as an evidence source; it is declarable and refused.
  • Desktop installers, signed builds, Windows or Linux desktop builds in CI, automatic updates.
  • nHapi and HL7apy profile metadata packs for versions other than the fourteen v2.5.1 segments that carry labels today.
  • Scheduling, daemons, watching a source, incremental or background work of any kind.
  • Full-text search, regular expressions, numeric or date ranges, cross-case search, and more than one question per index query.
  • Standard input or pipes: inputs are regular files.
  • Customer-derived engagement packets. report accepts its built-in synthetic scenario only.
  • Interactive terminal interfaces, configuration discovery, environment-variable precedence, hidden global config.

What results don't prove

  • Inspection is syntax. Field labels and states are not semantic validation or HL7 conformance.
  • The profile is narrow. readmit-siu-v1 covers SIU S12, S13, S15 and ACK for one SCH and one PID. It is a readmit fixture profile, not a vendor profile and not v2.5.1 conformance. No ADT or MPI state machine runs.
  • A clean diagnosis is not correctness. Only the listed rules were examined over the observed window, which may omit earlier or later events.
  • Equal wire fields are not delivery. A diff compares bytes; it does not establish that a receiver processed, stored or acted on anything.
  • An accept acknowledgement is not application processing. The collector applies nothing; a commit acceptance is not an application acceptance.
  • Reaching an endpoint is transport evidence. target check proves TLS and reachability, never that an application accepted a message.
  • A recorded classification is a claim. Labelling an endpoint nonproduction is not proof it is safe to send to; the label can only refuse.
  • A failed observation is not an empty one. A collector that never ran, stale data, a truncated capture, a lost connection or an ambiguous response observed nothing.
  • Redaction is not de-identification. Coverage and residual scans state their limits; no legal certification is made, and a digest of a short identifier is recoverable.
  • An offline entitlement cannot see a later revocation. The documentation states it rather than implies otherwise.
  • The synthetic packet says nothing about production. Its boundary is the built-in fixture's appointment ledger.
  • Discarding a package is unlinking. It is not erasure on a solid-state device, a copy-on-write filesystem, a snapshot, a backup, a replica or a recipient's machine.

Privacy posture, stated plainly

  • No telemetry, crash reporting, update checks, analytics or automatic uploads exist anywhere in the engine, the desktop shell, or this site.
  • Network access is limited to endpoints you explicitly configure. Inspection, capture, timeline and the desktop shell have no endpoint configuration at all.
  • Values are hidden unless --show-values is requested. Diagnostics name the declaration at fault and never repeat a value, a filename or a supplied argument.
  • Credentials and encryption keys are references readmit resolves by running your program; no command accepts a secret value and no value is ever written into a configuration, manifest, report, log or local browser state.
  • Run manifests, replays, indexes that retain values, and desktop saved filters can contain patient data. They are customer-local artifacts and are treated as such by the documentation.
  • Access control is the operating-system account and filesystem permissions. readmit has no accounts, no server and no store of its own.

Release requirements

  • Tag and publish a prerelease from current main so the archives match this site.
  • Capture desktop screenshots from a built release and add them here.
  • Publish license terms, support terms and the evaluation policy once counsel has reviewed them.
  • Signing credentials, installers and native installation tests for the desktop shell.
  • System, performance, security, privacy and accessibility acceptance (#109 and its siblings) before any finished-product claim.
