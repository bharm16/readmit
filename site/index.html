Reproduce an HL7 v2 incident locally, then prove the fix held.

readmit is a command-line tool, with a separate desktop shell, for healthcare integration engineers. It captures HL7 v2 evidence into verifiable case bundles, diagnoses a narrow scheduling profile, compares fields, replays selected messages to an explicitly approved test endpoint, evaluates declarative regression tests, and seals the evidence into a packet another person can verify offline. It runs on one machine, keeps evidence in plain directories, and opens no connection nobody configured.

Read this before anything else on this site. Every capability described here is implemented on the main branch and exercised by its test suite; nothing planned is presented as available. The one published archive, v0.1.0-alpha.2, predates almost all of it and contains readmit inspect only. To evaluate the rest today, build from source; see Download. There are no screenshots on this site because no built desktop release has been captured yet; none will be mocked. The support matrix is the authoritative list, and CLAIMS.md traces every statement on these pages to a documentation page and a test.

Features

Capture and verify evidence

Import HL7 files, folders, ZIP archives and CSV, JSON, XML or text envelopes into a versioned case bundle with a SHA-256 identity. Modifying a byte fails verification; nothing is ever overwritten.

Diagnose and compare

Evidence-bound findings for the readmit-siu-v1 scheduling fixture profile, separated into observed facts, profile violations and hypotheses. Field-aware diffs between files, cases, runs and results.

Replay and test safely

Previews by default. A send needs an explicit test target, and any non-loopback destination needs a policy naming it. Regression specs are strict JSON with no hooks; results retain the evidence they were judged on.

Receive, observe, collect

A bounded generic MLLP collector with original and enhanced acknowledgement modes and mutual TLS; observation windows over file exports and approved HTTPS APIs; collection from a directory or the customer's own transfer program.

Package for another person

Policy-driven redaction with a fail-closed export review, encrypted transfer packages under a key readmit never holds, and a sealed synthetic engagement packet with rerun instructions.

Keep credentials out of it

readmit registers references to credentials and keys held in an operating-system or customer-managed store. No command accepts a secret value, and a resolved value cannot be printed or serialized.

Limitations

  • Read a database. PostgreSQL, SQL Server and Oracle observation is selected and not implemented.
  • Read a Mirth Connect or Open Integration Engine export format. Not implemented.
  • Speak SSH or SFTP itself. A remote export is collected by running your own read-only client.
  • Validate HL7 conformance, run an ADT or MPI state machine, or certify a redaction as de-identification.
  • Send telemetry, check for updates, or phone home. None of that exists in the engine.

The complete list is on the limitations page.
