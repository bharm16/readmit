Supported workflows

Each workflow below is implemented on main, documented on the linked page, and exercised by a test named in CLAIMS.md. The boundary column says what a result does and does not establish; those sentences come from the documentation, not from this page. Commands read from explicitly named files and write only to a new destination they were given.

Bring evidence in

Reproduce and test

WorkflowCommandBoundaryDocumentation
Name a test environmenttarget set/show/checkcheck opens one connection, completes TLS and reports it; it never sends an HL7 payload. A recorded classification is a claim, not a finding, and can only ever refuse.target
Reset a fixturetarget reset --target FILE --plan FILE --outcome NEW_FILEActions come from a closed set of reviewed typed operators; the plan carries no command, script or interpreter. A reset readmit could not confirm is an execution error.target
Replayreplay CASE --target CONFIG [--send --output NEW_RUN --policy FILE]Previews without a connection. A send needs an explicit test target; a non-loopback destination needs a policy naming it; a production class refuses. Sent, received and uncertain outcomes are all recorded.replay
Regression testtest SPEC [--send --output NEW_RESULT]Exit 0 pass, 1 assertion failure, 2 execution error. Missing, stale, partial or mismatched observations are execution errors. Without --send there is no verdict.test runner
Durable runrun start SPEC --send --output NEW_JOB [--deadline], run status JOB [--recovery], run resume, run clean, run queue PLAN --send --runs DIRA synced plan and send journal; recovery reads evidence and never resends, resume repeats only never-attempted work into a new output, and clean removes only a stale lease. A queue runs several of those jobs at a declared parallelism, serializing every job that did not declare state isolation and refusing to join a run whose lease is still held.durable runs
Fixture receiverlistenOne SIU booking and rescheduling scenario with fixed and defective modes that both return AA; only the exported ledger tells them apart. Not a production receiver.listen
Generic collectorcollect --policy FILE --output NEW_DIRECTORY, collect status JOURNALAny message type over bounded MLLP, original and enhanced acknowledgement modes, TLS and mutual TLS, up to 64 peers. A commit acceptance is never an application acceptance.collect
Observation windowsobserve validate, observe explain, observe collect SOURCE --window WINDOW --out NEW_RECORD --snapshot NEW_DIRECTORYA window completes only when every sample observed and the state held still for the declared quiet period; a failed collection is never a passing absence assertion.observe
