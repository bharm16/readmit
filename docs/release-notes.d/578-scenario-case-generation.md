- Added `readmit scenario generate-case`, which generates executable ADT, SIU, order and result cases from a saved scenario under a pinned local profile and pack: messages built from the edition's own structures and data types, read back and evaluated before they are written, one phase per designed step, a resource's addition (S18) and cancellation of participation (S20), and a replacement as the two in turn, in a versioned `readmit-scenario/v2` workflow, written with HL7 segment action codes (or a declared snapshot convention), declared negative variants (duplicates, omitted prerequisites, reordering, delays recorded as execution timing, altered identities, null, empty, absent and invalid values, unlinked corrections), and a generation record with ancestry and a variant ledger. Events an edition does not support are named, never generated. Generation sends nothing and approves no expected outcome; a scheduled connected lifecycle (`readmit-connected-test/v6`) sends a generated case on the delays its generation declared, and the connected engine sends a generated case no other way. `readmit replay` sends a generated case only when `--ignore-scenario-timing` explicitly chooses byte-only replay, recorded as a `readmit-byte-only-run/v1` whose scenario timing was not applied.
